# AI 美术资源生产接口

本项目把“游戏逻辑”和“美术资源”彻底分离。Gemini Banana、人工绘制或其他工具都可以替换图片，不应该要求修改战斗、剧情、地图等核心代码。

## 1. 总原则

程序负责：

- 游戏状态、剧情、事件、战斗、行动顺序、五行弱点、奖励、地图节点、存档与场景切换。
- 角色在屏幕上的位置、缩放、层级、镜头和 UI 排版。
- 读取 `ArtAssetCatalog` 中登记的资源。

美术工具负责：

- 角色立绘 / 战斗精灵。
- 背景和场景。
- 敌人、NPC、特效、图标等。

不要让 AI 绘图工具决定游戏逻辑。

## 2. 资源接口

程序统一从 `scripts/presentation/art_asset_catalog.gd` 读取。

当前资源键：

### Characters

`WUKONG` / `TANG` / `BAJIE` / `WUJING` / `LONGMA` / `YELLOW_WIND`

### Scenes

`JOURNEY` / `BATTLE_YELLOW_WIND` / `WORLD_MAP`

生产资源优先使用 PNG 或 WebP；程序会保持 nearest-neighbour 像素过滤。

SVG 当前继续作为占位/可运行资源，不是最终美术标准。

## 3. Gemini Banana 角色生成标准

目标不是“卡通人物”，而是可以直接放进 JRPG 战斗画面的完整像素角色。

建议输出：

- 透明背景。
- 单角色全身。
- 正侧约 3/4 战斗姿态。
- 清晰轮廓。
- 可辨认脸部、发型/头饰、服装、鞋、武器、饰物。
- 明确的明暗分层。
- 低数量、高识别度的像素调色板。
- 像素边缘，不要抗锯齿。
- 不要 UI、文字、边框、水印。
- 不要把角色画成圆头+方身体的简化几何体。

## 4. 五人必须保持的视觉识别点

### WUKONG

猴脸、金箍、红色/深暖色战甲、金箍棒、尾巴，姿态偏进攻。

### TANG

僧帽、袈裟层次、法杖/经卷等识别道具，姿态克制、正直。

### BAJIE

猪面轮廓、体型明显更厚重、九齿钉耙、深色/土色服装。

### WUJING

高大厚重、卷发/胡须特征、月牙铲或禅杖、蓝灰/沙色视觉。

### LONGMA

白龙/白马特征、鬃毛、鳞片/龙角元素、速度感，不要画成普通马。

## 5. 战斗场景生成标准

战斗背景必须预留明确的角色站位区域：

- 我方通常在左侧。
- 敌方通常在右侧。
- 中央保留技能、伤害和镜头表现空间。
- 顶部保留 Action Queue。
- 右上保留 Target / HP / Weakness / Shield。
- 底部保留 Frame Status / Command。

不要把重要视觉主体塞进 HUD 占用的区域。

## 6. 场景生成标准

场景不是“风景壁纸”，而是游戏可读的舞台：

- 前景 / 中景 / 远景分层明显。
- 可供角色站立的地面清楚。
- 关键建筑或地标有识别度。
- 左右构图不要过于平均。
- 中央留给角色。
- 不需要自己绘制 UI。

## 7. UI 绝对规范

所有页面沿用 `docs/visual_reference/battle_ui_reference.webp`：

- 硬朗 2D 像素 JRPG。
- 45°切角装甲面板。
- 双层描边。
- 青绿色为主要信息高亮。
- 金色/橙色用于重要战斗状态。
- 深蓝黑底。
- 点阵、铆钉、分段状态条。
- 紧凑等宽/像素化字体优先。

禁止恢复网页卡片、圆角大白框、现代 SaaS 控制台式布局。

## 8. 换图流程

1. AI 生成资源。
2. 放入 `assets/art/...` 对应目录。
3. 根据资源类型登记到 `ArtAssetCatalog`。
4. 不修改 Domain / Narrative / Combat 逻辑。
5. 跑 Godot Runtime。
6. 跑 Web Demo。
7. 人工进入对应场景验收。

## 9. 当前阶段

现在优先完成非图片工程：

- 剧情运行链
- 战斗规则
- 奖励与世界动作
- Scene Handoff
- Save / Resume
- Vertical Slice

图片不足不会阻塞这些工作。最终美术资源可以后置替换。
