# 《西游：五行之路》游戏设计总方向

> This document is the project's canonical high-level direction. Future implementation should treat this as the source of truth unless explicitly revised.

## 1. 核心定位

**一句话定位：**

> 《八方旅人》的 JRPG 游戏框架 + 《西游记》百回小说的真实主线/人物事件 + “五方旅人”式五位主角结构 + 初版采用《重装机兵》时代的低资源像素/瓦片表现。

本项目不是文字冒险游戏。

文字、对话和事件只是剧情表现层；核心体验必须逐步具备：角色选择、角色个人序章、地图探索、城镇/NPC、随机/固定遭遇、回合制战斗、招募同伴、成长、装备、任务、存档，以及最终完整西游旅程。

## 2. 八方旅人参考范围

参考的是**游戏框架、角色结构和玩家体验**，不是照搬世界观。

重点参考：

- 开局从多个主角中选择一位作为自己的第一位旅人。
- 每位主角拥有独立的个人故事/序章/路线。
- 其他角色在旅途中相遇并逐步加入队伍。
- 世界地图、区域、城镇、迷宫和角色故事可以交叉汇合。
- 角色应当有明确职业定位、战斗特性和非战斗能力。
- 战斗强调弱点、破防、Boost/强化节奏等可理解的回合制策略。
- 角色立绘、头像、战斗表现和事件演出都是重要组成部分。

官方对 OCTOPATH TRAVELER 的描述同样强调“八位旅行者、八段冒险”和每个角色独立故事；系列战斗则强调弱点、Break 与 Boost。citeturn435870search1turn435870search2

本项目对应为：

> **五位旅人、五条出发视角、最终汇入同一条西游时间线。**

因此内部设计可以称为：**Five Travelers / 五方旅人**。

## 3. 五位旅人

当前五位核心主角：

- 唐三藏
- 孙悟空
- 猪八戒
- 沙悟净
- 白龙马

玩家可以选择任何一位作为开局视角。

选择角色不会改写西游世界的真实时间线；它只改变“玩家从谁的眼睛开始看到这段历史”。角色汇合后，世界继续沿固定西游 chronology 推进。

## 4. 剧情原则：西游小说优先

**剧情不是参考八方旅人的原创套路，而是以《西游记》原著为根。**

原则：

1. 主线事件以《西游记》真实小说文本为核心依据。
2. 人物身份、重要遭遇、妖怪、地点、师徒关系和大事件应尽量保持原著逻辑。
3. 可以为了 JRPG 节奏增加探索、战斗、支线、对话演出，但不得轻易把原著核心历史改成完全原创剧情。
4. 原著没有明确写出的内容，可以作为“游戏化补完”，但要和原著区分开。
5. 五位角色的个人序章，应尽可能把其原著出场前后的经历整理成可玩的个人故事。
6. 五条个人路线最终必须自然汇合到共同西游主线。

项目已经建立原著参考资料和章节索引，后续剧情实现应继续从这些资料扩展，而不是凭空创作整段西游主线。

## 5. 画面原则：先做出来，再升级

当前阶段**不追求八方旅人级 HD-2D 美术质量**。

目标是：

> **先用极低资源把一款真正能玩的西游 JRPG 做完整。**

第一阶段采用“古老 RPG / 《重装机兵》时代”思路：

- 像素化角色。
- 小尺寸角色精灵。
- TileMap/瓦片场景。
- 同一套瓦片通过排列组合制造大量地图。
- 少量动作帧循环实现走路、攻击、受击、待机。
- 场景使用颜色、明暗、地形和少量特效区分地点。
- UI、文字、图标尽可能复用。
- 战斗背景采用少量场景模板重复使用。
- 粒子、闪光、震屏等程序特效弥补素材不足。

《重装机兵》等老式 RPG 的资源组织本身就体现了大量角色/地图元素的复用方式；公开的精灵资源整理也能看到其 overworld、角色、敌人等采用大量小型可复用素材，而不是依赖现代高分辨率场景资产。citeturn435870search3turn435870search4

## 6. 资源效率目标

第一版应坚持“能省就省”：

- 优先 PNG/SVG/程序生成资源，不引入大体积视频。
- 音效优先程序化/短音频片段。
- BGM 可后置，不阻塞玩法开发。
- 地图使用共享 TileSet，而不是每个地点单独一整张大图。
- 人物采用少量基础动画帧 + 方向复用。
- 怪物采用基础模板变体：换色、装备、特征、尺寸、属性即可创造更多敌人。
- 战斗特效尽可能由粒子/绘制生成。
- 后续如果有条件制作高质量像素或 HD-2D 素材，应做到“替换资产即可升级”，而不是重写玩法代码。

## 7. 第一版完整体验目标

优先完成一条真正可玩的 Vertical Slice：

**主菜单 → 五方旅人选人 → 主角个人开场故事 → 可移动地图 → NPC/事件 → 第一次战斗 → 胜利奖励 → 获得成长/装备 → 第一个伙伴/关键事件 → 进入共同西游主线 → 存档/读档。**

只要这一条跑通，项目就已经从“剧情原型”变成“JRPG 原型”。

## 8. 战斗方向

战斗参考八方旅人的结构化回合制思路，但不机械复制数值系统。

长期目标：

- 普通攻击
- 技能/法术
- 属性与五行
- 敌人弱点
- Break/破防
- Boost/强化
- 状态效果
- 角色特性
- 装备
- 伙伴协同
- Boss 多阶段机制

“西游 + 五行”是本项目区别于普通复古 JRPG 的核心系统层。

## 9. 五行应成为核心玩法之一

项目名是《西游：五行之路》，五行不能只作为标题。

应逐步落实到：

- 角色能力
- 敌人属性
- 技能克制
- 环境机关
- 装备词条
- 地图区域
- Boss 机制
- 剧情选择
- 部分探索能力

五行系统可以先做简化版，待核心循环稳定后逐步深化。

## 10. 立绘/像素角色的阶段目标

### V0：程序占位

使用简单几何/程序绘制，只用于验证位置、UI 和玩法。

### V1：低成本像素化

为五位主角制作统一尺寸的像素角色、头像、战斗 sprite 和基础动作。

### V2：丰富角色表现

增加更多表情、动作、武器、技能特效、敌人精灵和 NPC。

### V3：HD-2D 升级

当玩法和内容稳定后，再考虑向“复古像素 + 现代景深/灯光/特效”的 HD-2D 方向升级。

这样可以保证美术升级不会破坏已经完成的游戏系统。

## 11. 音效方向

第一版只需要保证“操作有反馈”：

- 菜单移动
- 确认/取消
- 对话推进
- 物品获得
- 攻击
- 命中
- 受击
- Break
- 技能释放
- 胜利
- 失败
- 开宝箱
- 存档/读档

优先短、轻量、可程序化的音效；完整配乐体系放到后期。

## 12. 开发优先级

严格遵循：

**玩法完整度 > 内容完整度 > 可读性 > 资源规模 > 美术精度。**

不能为了某张漂亮背景图而停下地图、战斗、任务、成长等核心系统开发。

## 13. 一条长期判断标准

以后当出现“这个功能应该怎么做”的争议时，优先问：

> **它是否让《西游：五行之路》更像“一款五方旅人的西游 JRPG”，而不是更像一个文字剧情 Demo？**

如果答案是否定的，就不应该优先开发。

## 14. 当前技术原则

- Godot 4.5.1。
- 剧情数据与代码分离。
- EventSequence 作为统一剧情事件协议。
- 原著资料独立存放。
- 世界时间线固定，角色个人路线作为入口视角。
- 美术资源与玩法逻辑解耦。
- 所有未来像素/高清美术替换，都尽量通过资源替换完成。

---

**最终目标：**

> 先做一款“真的能玩”的《西游记》复古像素 JRPG，再把它一步步升级成我们理想中的“西游版八方旅人”。
