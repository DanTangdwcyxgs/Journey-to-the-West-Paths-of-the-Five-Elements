# 战斗队形规则

## 目标

五人队伍使用 `3 前排 + 2 后排`。队形不是纯 UI 编成，而是战斗构筑的一部分。

## 基础规则

- 前排最多 3 人。
- 后排最多 2 人。
- 角色可以在编成界面互换位置。
- 招募顺序只决定默认队形，不决定最终战斗位置。
- 已保存队形随存档恢复。

## 当前数值影响

角色进入战斗时会读取自己的行别，并应用 `party_profiles.json` 中对应的 `front_modifier` / `back_modifier`。

因此同一个角色放在不同位置，可以得到不同的防御与速度组合。

此外，后排角色在正常、未 Break 的状态下受到单体攻击时，当前基础伤害倍率为 `0.85`。这使后排天然更安全，但不会成为绝对安全区。

## 战术意图

### 前排

适合：

- 猪八戒等高生存角色
- 需要稳定承受攻击的角色
- 希望更快参与正面输出的构筑

代价：

- 更容易承担单体伤害
- 某些角色的前排速度修正更低

### 后排

适合：

- 唐三藏等辅助
- 沙悟净等控制
- 需要保留行动能力的角色

代价：

- 不同角色可能牺牲部分防御
- 未来的近战限制、射程、范围技能等规则会继续区分前后排价值

## 与 Break / BP 的关系

后排保护不能替代 Break。

玩家的主要战术循环仍然是：

`识别弱点 → 压低护盾 → Break → 利用 BP 爆发 → 结束危险目标`

队形的作用是让玩家决定“谁承担风险、谁保存行动能力、谁负责破防、谁负责爆发”。

## 后续扩展

这一层目前只定义基础位置语义。后续可以逐步加入：

1. 前排/后排专属技能标签。
2. 只能攻击前排的敌人招式。
3. 穿透后排的范围技。
4. 嘲讽与护卫，把“保护后排”转成角色专属机制。
5. 白龙马变身对队形与目标优先级的改变。

这些扩展必须保持与现有 `CombatEngine`、`PartyManager`、`NarrativeState` 解耦，避免再次重写存档结构。
